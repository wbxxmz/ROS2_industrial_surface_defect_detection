# 扩展 04：一键启动与打包交付（双击即用）

> 版本：V1.2.1（扩展 03 的交付增强）｜ 所属模块：启动入口 + 分发形态
> 背景：扩展 03 只交付了「服务 + 拖拽页」，启动仍要求终端执行 `uvicorn ...`；本扩展把「零终端」补齐。
> 约束：仍遵守 P5 无头原则——只起本地服务并调系统浏览器，不引入桌面 GUI 框架。

## 1. 目标

- 让**完全没有编程经验**的使用者在不打开终端的前提下完成：**双击图标 → 浏览器自动打开 → 拖入一张图 → 看到 PASS/FAIL、标注图与缺陷明细**。
- Linux（答辩 / 演示机）优先：`start_web.sh` + `.desktop` 双击入口，本机可完整验收。
- Windows（仅在确有必要时）：PyInstaller 打包 **OpenCV-only** 版 exe；YOLO 版不承诺、不默认交付。
- 明确边界：本扩展**只解决「怎么启动、怎么分发」**，不改变检测能力、判定口径与阈值。

## 2. 契约影响

- **不改动** `Detection` / `Frame` / `Verdict` / `Detector` / `InputSource` 任何字段与语义；不改 `CLASS_MAP`（`scratch:0 / dent:1 / stain:2 / notch:3`）。
- **不改** `configs/*.yaml` 的任何阈值；启动器只做「选哪份配置」，不做调参。
- 异常语义沿用既有约定：启动器只做前置自检 + 中文提示 + 非零退出码，不打印裸 traceback，不吞异常。
- 新增文件（不改变既有模块职责）：`start_web.sh`、`start_web.desktop`、`packaging/`（spec / 构建脚本 / CI 工作流）。
- 唯一可能触及既有代码的点：**冻结（frozen）场景的路径解析**。若做 exe，需把 `web/app.py:24-25`（`PROJECT_ROOT` / `DEFAULT_CONFIG_PATH`）、`web/routes.py:34`（`STATIC_DIR`）、`web/routes.py:94-95`（`output_dir` 及其 `mkdir`）收敛到一个小工具（如 `utils/paths.py`：资源根 + 可写根）。要求：源码运行时行为与现在完全一致，`tests/test_web.py` 不需改断言。
- 无头约束不变：不引入 PyQt / pywebview / Electron 等 GUI 窗口。

## 3. 核心方案

### 3.1 A 路线：Linux 双击启动（先做，本机可验收）

`start_web.sh` 流程：

1. 定位项目根目录，校验 `python3` 存在且 ≥ 3.10；
2. 依赖自检（`cv2` / `numpy` / `yaml` / `reportlab` / `openpyxl` / `matplotlib` / `fastapi` / `uvicorn` / `python-multipart`），缺失时打印中文安装命令并以 `2` 退出（复用 `run_demo.sh` 的提示风格）；
3. 配置选择：`best.pt` 存在且 `ultralytics` 可导入 → `configs/html_yolo_demo.yaml`；否则回退 `configs/html_demo.yaml`（纯 CPU），并打印回退原因；
4. 端口探测：8000 → 8001 → 8002，最多 3 个，全部占用则报错退出；
5. 后台启动 `uvicorn web.app:create_app --factory --host 127.0.0.1 --port <p>`，轮询 `GET /` 直到 200（超时 30 s 报错并退出）；
6. `xdg-open http://127.0.0.1:<p>` 打开浏览器；服务日志写 `reports/web/server.log`（已被 `.gitignore` 忽略）；
7. `Ctrl+C` 或关闭终端 → 结束子进程并释放端口。

`start_web.desktop`：`Exec=<项目根>/start_web.sh`，`Terminal=true`（保留可见提示与错误信息，避免"双击没反应"）；部分发行版首次需右键「允许运行」，README 必须写明。

### 3.2 B / C 路线：Windows exe（可选，本机不可验证）

- `packaging/launcher.py`：入口脚本，起 uvicorn 线程 → `webbrowser.open` → 退出时清理；
- `packaging/app.spec`：datas 打包 `web/static/`、`configs/*.yaml`；hiddenimports 覆盖 uvicorn / fastapi / python-multipart 的动态导入；
- `packaging/build_exe.bat`：Windows 侧 `pip install -r requirements.txt pyinstaller` → `pyinstaller packaging/app.spec`；
- `.github/workflows/build-exe.yml`：`windows-latest` 构建并上传 artifact（需用户授权 push）；
- 冻结后路径：资源从 `sys._MEIPASS` 读，报告与日志写用户可写目录（如 `~/Documents/defect_reports/`），**不写临时解包目录**（否则退出即丢）；
- 只打 OpenCV 版：`best.pt` + torch 会让产物达 GB 级并依赖 CUDA 驱动，不作为默认交付物。

### 3.3 明确不做

- 不为演示好看而调阈值、改判定口径。
- 不做公网部署 / 鉴权 / 多用户：保持 `127.0.0.1` 本地绑定，仅作演示服务。
- 不引入 GUI 框架（会破坏 `CLAUDE.md`「无头」硬约束）。
- 不承诺 Windows exe 的「已验证可用」——本机无 Windows / 无 wine，验证责任见 §4。

## 4. 验收标准

**A 路线（Linux，本机可验收）**

- [ ] 缺依赖：双击 → 中文提示 + 安装命令，退出码 2，无 traceback。
- [ ] 有依赖、无 `best.pt`：自动用 OpenCV 配置，页面不显示注意力热力图区域，拖图仍出结果。
- [ ] 有 `best.pt` + `ultralytics`：自动用 YOLO 配置，首请求后展示注意力热力图。
- [ ] 8000 被占用：自动改用 8001，终端打印实际 URL，浏览器打开的是同一地址。
- [ ] 拖入 `test_picture/inclusion_174.jpg`：PASS/FAIL、标注图、缺陷明细与同配置 CLI 结果逐字段一致。
- [ ] 关闭终端 / 进程：端口释放（`ss -ltn | grep :80` 无残留）。

**B / C 路线（在 Windows 机器上执行，本仓库 CI 只保证构建成功）**

- [ ] 双击 exe → ≤10 s 浏览器自动打开；拖图出结果；关闭 exe 进程后端口释放。
- [ ] 报告落在用户可写目录，进程退出后文件仍在。
- [ ] 产物体积 ≤ 300 MB（OpenCV 版，不含 torch）。
- [ ] 无 `best.pt` 时同样能跑，并在终端/日志明确提示「当前为 OpenCV 路线」。

**回归**

- [ ] `python3 -m pytest -q` 全绿（`tests/test_web.py` 不因路径改造变化）。
- [ ] `./run_demo.sh opencv`、`python3 main.py --config configs/demo.yaml` 行为不变。

## 5. 风险说明

- **exe 无法本机验证**：PyInstaller 不支持交叉编译，本机为 Linux 且无 wine / Windows，B/C 路线必须由 Windows 机器或 CI 承担验证；未验证前不得对外宣称「exe 可用」。
- **未签名 exe**：Windows 首次运行会触发 SmartScreen「未知发布者」；PyInstaller 产物也可能被杀软误报，对外分发需提前说明。
- **onefile 启动慢**：解包 3–10 s，首次请求还要加载模型；页面已有「处理中…（首次请求会加载模型）」提示。
- **Windows wheel 风险**：`requirements.txt` 锁定 `PyYAML==5.4.1`、`opencv-python-headless==5.0.0.93`，在 Windows + 新 Python 上可能没有现成 wheel，打包前需实测并评估是否放宽版本（放宽须记入文档，不得悄悄改）。
- **`.desktop` 双击限制**：部分发行版默认不允许双击运行脚本，需右键「允许运行」或设置可执行位；README 必须写清这一步。
- **路径改造是唯一风险点**：一旦引入资源根 / 可写根，必须保持源码运行默认行为不变，并由既有 Web 测试守住。
