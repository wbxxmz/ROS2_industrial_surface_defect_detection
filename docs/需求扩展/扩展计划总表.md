## 一、扩展原则

| 编号 | 扩展原则 | 说明 |
| --- | --- | --- |
| P1 | **契约冻结不破坏** | 只新增可选字段（如 `Verdict` 现新增的 `max_severity`），不改既有字段名/类型/单位/语义；defect 四类映射表（scratch:0 / dent:1 / stain:2 / notch:3）全链路复用，禁止重复定义 |
| P2 | **配置驱动、阈值不写死** | 所有算法阈值、判定规则、分级权重、报告格式一律经 `load(cfg)` 或 `configs/*.yaml` 传入，代码零硬编码 |
| P3 | **单一抽象接口接入** | 新检测器实现 `Detector`（load/detect/name/version/release），新输入源实现 `InputSource`（open/read/close），在工厂中仅增加一个分支注册，不改主流程 |
| P4 | **独立可验收** | 每个模块单独交付、单独验收，不阻塞主流程；落地前先写清「解决什么业务问题 + 用什么量化指标证明价值」 |
| P5 | **无头优先 / 服务化** | 延续无头架构；需要交互时以服务形态（Web / ROS2 节点）暴露，不引入桌面 GUI |
| P6 | **双框架对齐** | Python CLI 与 ROS2 两套实现共享同一契约、同一异常语义、同一配置口径，改一处须同步另一处 |
| P7 | **可复现 / 确定性强** | 同一输入 + 同一配置多次运行结果逐字段一致（仅允许浮点尾差），批处理结果（计数 / is_pass / total_count）必须确定 |
| P8 | **异常语义规范** | 加载失败抛 `DetectorLoadError`、推理失败抛 `DetectorInferenceError`、输入打开失败抛 `SourceOpenError`；空输入返回 `[]` 或抛 `ValueError`，不静默吞错 |
| P9 | **演示价值优先（本轮排序依据）** | 在满足 P1–P8 的前提下，扩展顺序按「可视化强度 + 改动复杂度 + 求职/答辩增益」排序：能短期产出**可截图 / 可录屏 / 可现场演示**成果的模块优先，重 ML 与基础设施类后置 |

## 三、扩展落地规范

> 每个扩展模块落地时，必须遵守以下规范，确保「增量不破坏」与双框架一致性。

| 规范项 | 落地要求 | 对应原则 |
| --- | --- | --- |
| 契约合规 | 新增字段只追在 dataclass 末尾；`severity` 沿用 `Optional[int]`（取值 {None,0,1,2}）；用 `dataclasses.replace` 生成新对象，**不改入参**；空输入返回 `[]` 不返回 `None` | P1 / P8 |
| 配置接入 | 新阈值一律写入 `configs/*.yaml` 对应段；整段缺失用默认值、可选字段缺失逐个取默认、非法值抛 `ValueError`、必填默认键缺失抛 `ValueError` | P2 |
| 工厂注册 | 新增检测器在 `pipeline.build_detector` 的 `detector.type` 分支注册一个 `return`；新增输入源在 `inputs/factory.py` 注册；不复制业务逻辑 | P3 |
| 异常语义 | 加载失败 `DetectorLoadError`、推理失败 `DetectorInferenceError`、打开失败 `SourceOpenError`、读取中断 `InputSourceError`，统一继承 `ProjectError`；`main.py` 转换为可读提示并返回非零退出码 | P8 |
| 测试规范 | 每个模块补单元测试，覆盖：契约字段校验、异常语义、边界过滤、置信度范围、类映射一致性；给出 `python3 -m pytest -q tests/...` 验收命令 | P4 |
| 双框架同步 | 涉及 `Detection` / `Verdict` / msg / srv 契约或 cfg 口径变更时，Python `core/` 与 ROS2 `src/defect_interfaces` **同步更新** | P6 |
| 文档联动 | 更新对应阶段文档字段清单、README 目录结构与性能基线表；报告/可视化口径与 judge 判定阈值严格一致（复用同一配置） | P4 |
| 版本与提交 | 计划完成版本号写入模块头注释；提交信息遵循 `feat(stageX): <说明>`，扩展项单独立项不混入无关改动 | P4 |

## 五、风险与注意事项

- **演示优先 ≠ 华而不实**：V1.1–V1.3 的先做是为求职「快速拿出可展示成果」，但每项仍须落实 P8 的异常语义与测试，不得只做「能截图」的半成品。
- **契约是底线**：任何扩展不得改动 `Frame` / `Detection` 既有字段，只增可选字段；一旦破坏，阶段 3/4/5/6/7 需同步返工。
- **双框架漂移**：Python 与 ROS2 长期并行易产生口径漂移，落地规范「双框架同步」必须强制。
- **无监督 / 小样本评估陷阱**：避免「全判正常也高分」的假象，评测须用类别不平衡指标（召回 / 精确率 / F1）。
- **加速与精度权衡**：量化 / TensorRT 需先验证精度降幅可控再上线，避免「快了但漏检」。
- **EigenCAM 版本耦合**：EigenCAM 虽不做反向传播，但仍依赖 `ultralytics` 的 backbone 层索引，升级 / 更换 `ultralytics` 版本后必须重新确认 hook 层，否则会取到错层特征或报错。
- **Web 服务的安全与依赖边界**：演示服务需限定输入大小、异常回退，避免把本地推理环境暴露成不可控的外部服务。
