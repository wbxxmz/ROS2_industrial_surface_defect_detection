# 阶段 2：输入源实现 · 实现技术文档

## 1. 阶段目标

实现图片、视频、摄像头三种输入源，统一产出"帧对象"供流水线后端消费，屏蔽来源差异。

## 2. 前置条件与依赖

- 依赖阶段 1 的 `InputSource` 抽象基类与流水线骨架。
- 依赖 OpenCV（`cv2.VideoCapture` / `cv2.imread`）等基础依赖已就位。

## 3. 工作分解（WBS）

1. 实现图片输入：单张读取 + 批量目录导入。
2. 实现视频输入：逐帧读取、抽帧/跳帧、随机定位。
3. 实现摄像头输入：本地 USB 摄像头 + RTSP 网络流。
4. 实现统一帧对象与帧队列（供实时流缓冲）。
5. 实现输入源工厂/注册，按配置实例化对应子类。

## 4. 关键技术方案

### 4.1 三个子类

| 子类 | 来源 | 关键点 |
| --- | --- | --- |
| `ImageSource` | 本地图片 / 目录 | 目录批量排序、小内存分批处理 |
| `VideoSource` | 本地视频文件 | 帧索引定位、跳帧抽帧、循环播放控制 |
| `CameraSource` | USB / RTSP | 后台线程读帧入队，防止阻塞 |

### 4.2 统一帧对象

所有来源的 `read()` 返回统一 `Frame`，字段与阶段 0 §5.4.4 冻结表逐字一致，不得增删改字段名/类型/单位：

| 字段 | 类型 | 单位/口径 |
| --- | --- | --- |
| image | np.ndarray，uint8，H×W×3，BGR 通道 | 需 RGB 的算法在检测器内部自行转换，帧对象本身不改 |
| width | int | 像素，对应 image.shape[1] |
| height | int | 像素，对应 image.shape[0] |
| frame_index | int | 从 0 起的源帧序号；跳帧时仍为源帧号 |
| timestamp | float | 秒，从源起点算；图片为 0.0 |

所有字段不可为 None；图片的 `timestamp` 为 0.0（见阶段 0 §5.4.4）。

### 4.3 实时性处理

- **线程模型（实现定稿）**：仅 `CameraSource` 用**生产者-消费者**（后台线程 + 帧队列）；`ImageSource`、`VideoSource` 为同步读取、不启线程，保持确定性以便逐帧断言。
- **取帧策略**：`CameraSource.read()` 阻塞取帧；队列空则阻塞等待生产者入队，仅在「线程已退出且队列耗尽」时返回 `None`（即读尽）。不得因「队列暂时为空」返回 `None`——这违反契约「None 只表示读尽」的语义。
- **错误暴露顺序**：队列中已捕获的帧先交付，队列取空且线程退出后才抛 `InputSourceError`——断流不得丢弃已捕获的有效帧。
- **队列满策略**：帧队列设固定容量（默认 8，`source_cfg.queue_size` 可调）；队列满时丢弃最旧帧（drop-oldest），保留最新帧。
- **跳帧**：每 N 帧取一帧检测（`source_cfg.step`，默认 1 即不跳）。跳帧只影响「哪些帧被送入检测」，不改变 `frame_index`——`frame_index` 恒为源帧序号，见阶段 0 §5.4.4；`CameraSource` 重连成功后 `frame_index` 继续递增（不重置为 0）。
- **时间戳口径**：`ImageSource` 恒为 0.0；`VideoSource` 取 `frame_index / fps`；`CameraSource` 取 `time.monotonic()` 相对 `open()` 的秒数。
- **线程退出**：`close()` 置停止标志 → 生产者线程退出取帧循环 → `read()` 发现停止且队列耗尽返回 `None`；线程为普通线程（非 daemon），`close()` 内 `join(timeout)` 等待退出；重连等待须用可被 `close()` 打断的方式实现，避免关闭时挂起。

### 4.4 输入源注册

- 通过工厂函数按 `config.input.type` 创建 `ImageSource / VideoSource / CameraSource`。
- `source_cfg`（`open()` 入参，阶段 0 §5.4.3 规定为 dict，本阶段冻结字段结构；用 `TypedDict` 或 `@dataclass` 约束，不用裸 dict）：

| 字段 | 类型 | 适用源 | 说明 |
| --- | --- | --- | --- |
| type | str | 全部 | 必填，取值 `image` / `video` / `camera` |
| path | str | image / video | 单张图片或视频文件路径 |
| dir | str | image | 图片目录（与 `path` 二选一） |
| extensions | list[str] | image | 目录导入扩展名白名单，默认 `[".jpg",".jpeg",".png",".bmp"]` |
| step | int | video / camera | 跳帧步长，默认 1（不跳） |
| loop | bool | video | 是否循环播放，默认 false |
| start_frame / end_frame | int | video | 可选，播放区间（含端点帧号） |
| device_id | int | camera | USB 摄像头编号（与 `url` 二选一） |
| url | str | camera | RTSP/网络流地址（与 `device_id` 二选一） |
| queue_size | int | camera | 帧队列容量，默认 8 |
| timeout | float | camera | RTSP 单次阻塞超时（秒），默认 5.0 |
| reconnect | bool | camera | 断流是否自动重连，默认 true |
| reconnect_interval | float | camera | 重连间隔（秒），默认 2.0 |
| reconnect_max | int | camera | 重连次数上限，默认 5，超出抛 InputSourceError |

补充约定：

- `source_cfg` 出现上表以外的字段 → 抛 ValueError（便于发现拼写错误），不静默忽略。
- 工厂 `build_source(source_cfg)` 返回**未 open** 的输入源实例，调用方需自行 `open(source_cfg)`。

## 5. 关键接口落位

三个子类实现 `InputSource`，方法契约与阶段 0 §5.4.3 逐字一致，不得改签名：

| 方法 | 返回类型 | None 语义 | 异常语义 |
| --- | --- | --- | --- |
| open(source_cfg) | None | 不可 None | 文件不存在 / 图片损坏 / 摄像头占用 / RTSP 打开失败抛 SourceOpenError，由调用方捕获 |
| read() | Frame 或 None | None 只表示读尽/结束；出错抛 InputSourceError | 运行中流中断抛 InputSourceError |
| close() | None | 不适用 | 应幂等：重复调用不抛异常、不重复释放；用关闭标志位判定 |

边界与错误语义（可判定）：

- `open()`：图片/视频文件不存在、图片无法解码、摄像头被占用、RTSP 连接失败 → 抛 SourceOpenError。
- `read()`：文件源读到末尾 → 返回 None（读尽）；中途解码失败/流中断 → 抛 InputSourceError；空图片（`imread` 为 None）或尺寸 0 → 抛 InputSourceError。
- 单帧视频：第一次 read 返回该帧，第二次 read 返回 None（读尽）。
- 未调用 `open()` 就 `read()`：抛 InputSourceError（视为误用）。
- `close()` 之后再 `read()`：返回 None（视为读尽），不抛异常。
- 三个子类不得把 `NotImplementedError` 作为契约异常（那是基类占位，见阶段 1）。

## 7. 阶段要求与验收标准

- 三种来源均能稳定产出帧，喂给阶段 1 的占位流水线不报错。
- 视频/摄像头支持播放、暂停、逐帧、跳帧。
- 摄像头断流/未连接时能优雅报错而非崩溃。
- 批量目录导入能正确遍历并按序处理。
- 契约一致性：三子类的 open/read/close 签名、返回类型、None 语义与阶段 0 §5.4.3 逐字一致；帧对象字段与 §5.4.4 冻结表逐字一致（可用脚本打印各字段 type 与契约比对判定）。
- 跳帧语义：视频按 step=3 跳帧时，产出的 `frame_index` 仍为源帧序号（0,3,6…），可脚本断言。
- 队列与重连：队列满时读到的是最新帧、最旧帧被丢弃；断流重连用尽后 read 抛 InputSourceError；close 连调两次不抛异常。
- 图片目录导入按文件名/序号排序，顺序遍历且无重复、无遗漏。
- 非法参数校验：`step`、`queue_size` 等取值 ≤0 时，在构造/open 时抛 ValueError 或 SourceOpenError。
- 单测覆盖（实现验收证据）：三源 + 契约一致性 + 工厂共 49 例通过，含签名逐字比对、Frame 字段顺序、跳帧源帧号、队列满丢旧、断流重连用尽、close 幂等与线程无泄漏。

## 8. 风险与注意事项

- RTSP 流延迟、断线重连是常见坑，行为已写死：单次阻塞超时 `timeout`（默认 5s）、断流判定为连续 read 失败、自动重连（`reconnect` 默认开）、重连间隔/次数可配（默认 2s / 5 次）、重连用尽抛 InputSourceError；数值见 §4.4。
- 分辨率差异影响后续面积计算，帧对象已冻结携带 width/height（见 §4.2）。
- 批量导入大目录时注意内存占用，图片目录按需读取、不整体载入。
- 实时流「空队列」与「读尽」必须区分：空队列阻塞等待，读尽才返回 None，否则违反阶段 0 契约（见 §4.3 取帧策略）。

## 9. 与其他阶段衔接

- 阶段 3、4 的检测器直接消费本阶段帧对象。
- 阶段 5 的可视化需要帧的 `width/height` 与时间戳做标注和回放。
