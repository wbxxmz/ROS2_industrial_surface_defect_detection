# 阶段 2：输入源实现 · 实现技术文档

## 1. 阶段目标

实现图片、视频、摄像头三种输入源，统一产出"帧对象"供流水线后端消费，屏蔽来源差异。

## 2. 前置条件与依赖

- 依赖阶段 1 的 `InputSource` 抽象基类与流水线骨架。
- 依赖 OpenCV（`cv2.VideoCapture` / `cv2.imread`）等基础依赖已就位。

## 3. 工作分解（WBS）

1. 实现图片输入：单张读取 + 批量目录导入。
2. 实现视频输入：逐帧读取、抽帧/跳帧、随机定位。
3. 实现摄像头输入：本地 USB 摄像头 + RTSP 网络流。
4. 实现统一帧对象与帧队列（供实时流缓冲）。
5. 实现输入源工厂/注册，按配置实例化对应子类。

## 4. 关键技术方案

### 4.1 三个子类

| 子类 | 来源 | 关键点 |
| --- | --- | --- |
| `ImageSource` | 本地图片 / 目录 | 目录批量排序、小内存分批处理 |
| `VideoSource` | 本地视频文件 | 帧索引定位、跳帧抽帧、循环播放控制 |
| `CameraSource` | USB / RTSP | 后台线程读帧入队，防止阻塞 |

### 4.2 统一帧对象

所有来源的 `read()` 返回统一帧结构，至少携带：

- `image`：原始像素（BGR 或约定格式）。
- `width` / `height`：分辨率。
- `frame_index` / `timestamp`：索引与时间戳（用于报告溯源与视频对照）。

### 4.3 实时性处理

- 摄像头/视频用**生产者-消费者**模式：独立线程读帧放入队列，主流程取最新帧，避免检测速度慢于帧率时积压。
- 提供跳帧参数：每 N 帧检测一次，兼顾实时性与算力。

### 4.4 输入源注册

- 通过工厂函数按 `config.input.type` 创建 `ImageSource / VideoSource / CameraSource`。

## 5. 关键接口落位

- 实现 `InputSource` 的三个子类，`read()` 返回统一帧对象。
- `open()` 处理打开失败（文件不存在、摄像头占用、RTSP 断流）并给出可读报错。

## 6. 交付物

- 三个输入源子类 + 工厂注册。
- 帧对象数据结构。
- 各来源的演示脚本/冒烟测试。

## 7. 阶段要求与验收标准

- 三种来源均能稳定产出帧，喂给阶段 1 的占位流水线不报错。
- 视频/摄像头支持播放、暂停、逐帧、跳帧。
- 摄像头断流/未连接时能优雅报错而非崩溃。
- 批量目录导入能正确遍历并按序处理。

## 8. 风险与注意事项

- RTSP 流延迟、断线重连是常见坑，需预留超时与重连。
- 分辨率差异影响后续面积计算，帧对象务必携带分辨率。
- 批量导入大目录时注意内存占用，采用分批/流式处理。

## 9. 与其他阶段衔接

- 阶段 3、4 的检测器直接消费本阶段帧对象。
- 阶段 5 的可视化需要帧的 `width/height` 与时间戳做标注和回放。
