# 阶段 5：结果可视化与判定 · 实现技术文档

## 1. 阶段目标

把检测结果直观地"画出来、判出来、统计出来"：边界框/掩码叠加、面积与置信度标注、单件合格/不合格判定、缺陷统计汇总。

本阶段为**无头（headless）架构**：只做纯后台图像绘制与结构化输出，不开发任何 GUI（不含 PyQt 等桌面窗口、不含 `cv2.imshow` 实时窗口）。标注图落盘为 jpg，界面层留给后续 Web 端或 ROS2 节点。

## 2. 前置条件与依赖

- 依赖阶段 3/4 的检测器输出 `List[Detection]`；四类 `class_id`/`class_name` 映射表复用阶段 3 §4.1（`0=scratch、1=dent、2=stain、3=notch`），本阶段只读、不重定义。
- 依赖阶段 2 的帧对象 `Frame`（`image`/`width`/`height`/`frame_index`/`timestamp`，含分辨率用于坐标与面积换算）。
- 运行依赖：`numpy`、`opencv-python`（`cv2`）；**不依赖任何 GUI 框架**，进程无需 `DISPLAY` 亦可运行。
- 判定规则的阈值全部来自配置文件（见 §4.2.2），本阶段不引入新的检测算法。

## 3. 工作分解（WBS）

1. 叠绘模块：边界框（含类别颜色）、掩码半透明叠加、类别标签。
2. 信息标注：面积、置信度、严重度（预留）绘制到图上；画面全局 PASS/FAIL 提示。
3. 判定模块：单件产品合格/不合格规则（缺陷数量、面积占比、严重度上限），规则参数全部配置化。
4. 统计汇总：缺陷总数、分类计数、良率、缺陷面积汇总，输出**结构化数据**（供阶段 7 复用），不绘制 UI 面板。
5. 无头输出接入：按帧把标注图保存为 jpg（路径由调用方指定），不弹窗、不开窗口；界面交给后续 Web 端 / ROS2 节点，不在本阶段范围。

## 4. 关键技术方案

### 4.1 叠绘

- 不同缺陷类别用**固定颜色映射**（BGR，不随配置变化），便于一眼区分，且与阶段 3 调试脚本配色一致：

| `class_id` | `class_name` | BGR 值 | 视觉 |
| --- | --- | --- | --- |
| 0 | scratch | `(0, 0, 255)` | 红 |
| 1 | dent | `(255, 0, 0)` | 蓝 |
| 2 | stain | `(0, 255, 0)` | 绿 |
| 3 | notch | `(0, 165, 255)` | 橙 |

  `class_id ∉ {0,1,2,3}` 时用白色 `(255, 255, 255)` 绘制并记 `warning`，不抛异常（与阶段 4 §4.2「越界只丢弃/降级」的宽松策略一致）。

- **线宽与字号按分辨率缩放**（固定公式，避免高分辨率下文字过小）：

  - 线宽 `thickness = max(1, round(min(W, H) / 400))`；200×200 → 1，800×800 → 2，2000×2000 → 5。
  - 字号 `font_scale = max(0.4, min(W, H) / 1000)`。
  - 文字统一 `cv2.FONT_HERSHEY_SIMPLEX`，描边 1 px 深色以保证浅色背景下可读。
  - 绘制坐标用整数像素、原点左上（与阶段 0 §5.4.1 `bbox` 口径一致），绘制前 clamp 到 `[0,W]×[0,H]`。

- 边界框叠加 + 标签文本，标签格式固定为 `"{class_name} {confidence:.2f}"`；若调用方要求显示面积，追加 `" a={area_px}"`（同一行）。
- 若 `Detection.mask` 非 `None` 且尺寸与图像一致，用该类别颜色的半透明填充展示缺陷实际形状（`alpha = 0.35`）；`mask` 为 `None` 或尺寸不一致时跳过填充、照画框，尺寸不一致记 `warning`。
- **全局判定提示**：在画面左上角绘制横幅文字，良品为绿色 `PASS`（BGR `(0, 200, 0)`），次品为红色 `FAIL`（BGR `(0, 0, 255)`）；字号 `max(0.8, min(W, H) / 500)`，线宽 2，文字前铺一层同色半透明底条以保证可读。
  - **`List[Detection]` 为空时仍然绘制 `PASS`**：空列表表示"未检出缺陷"，由判定模块给出 `is_pass=True`，可视化按 `verdict` 绘制，不因"没东西可画"而省略横幅。
  - 横幅文字只由 `verdict.is_pass` 决定，不得由 `len(detections)` 自行推断（避免判定与画面口径分裂）。

### 4.2 判定规则

#### 4.2.1 有效缺陷与规则集

先筛出**有效缺陷**（同时满足）：`confidence ≥ min_confidence` 且 `area_px ≥ min_area_px`。仅有效缺陷参与判定与计数；被筛掉的检测仍可按原样绘制（便于人工复核）。

规则按固定顺序求值，**任一命中即 `is_pass=False`**；`reason` 汇总全部命中项（用 `"；"` 连接），无命中时为 `"PASS：未检出有效缺陷"`（有效缺陷数为 0 时）或 `"PASS：未触发判定规则"`：

| 规则 id | 判定条件 | 说明 |
| --- | --- | --- |
| `count` | 有效缺陷数 `> max_count` | 数量上限，含等于通过 |
| `area` | 有效缺陷 `area_ratio` 之和 `> max_area_ratio` | 面积占比上限；求和结果 clip 到 `[0,1]` 后再比较 |
| `severity` | 任一 `severity` 非 `None` 且等级高于 `max_severity` | 阶段 6 前 `severity` 恒为 `None`，本阶段该规则**恒不触发** |
| `class:count:<id>` | 该 `class_id` 的有效缺陷数 `> per_class[id].max_count` | 仅当该类在 `per_class` 中显式配置时启用 |
| `class:area:<id>` | 该 `class_id` 的有效缺陷 `area_ratio` 之和 `> per_class[id].max_area_ratio` | 同上 |

**优先级语义（唯一口径）**：全局规则（`count`/`area`/`severity`）与类内规则（`class:*`）是逻辑"与"关系——两者同时生效、各自独立判断，任一超限即 `FAIL`；`per_class` 只增加类内约束，**不替换、不收敛**全局阈值。同一 `class_id` 不允许在 `per_class` 中重复配置。

#### 4.2.2 判定配置表（配置驱动，禁止写死）

判定函数接收 `cfg = config["judge"]`（与阶段 3/4「整段配置下发」一致）；`cfg` 为 `None` 或 `{}` 时全部取下表默认值。

| 字段 | 类型 | 默认值 | 校验规则 |
| --- | --- | --- | --- |
| `max_count` | int | `0` | 非 bool 的 int 且 `≥ 0`；`0` 表示"不允许任何有效缺陷" |
| `max_area_ratio` | float | `0.01` | 数值且落在 `[0, 1]` |
| `min_confidence` | float | `0.45` | 数值且落在 `[0, 1]` |
| `min_area_px` | int | `10` | 非 bool 的 int 且 `≥ 0` |
| `max_severity` | null | `null` | **本阶段只接受 `null`**；配置非 `null` 抛 `ValueError`（阶段 6 才启用） |
| `per_class` | dict | `{}` | 键为 `class_id`（0~3 的 int）或 `class_name`；值为 `{max_count?, max_area_ratio?}`，未知子字段抛 `ValueError` |

配置示例（写入现有 `configs/*.yaml` 顶层，不改动 `input`/`detector` 段）：

```yaml
judge:
  max_count: 0
  max_area_ratio: 0.01
  min_confidence: 0.45
  min_area_px: 10
  max_severity: null      # 阶段 6 前必须为 null
  per_class:
    0: {max_count: 2, max_area_ratio: 0.005}   # 划痕允许 2 条、面积占比 0.5%
```

### 4.3 统计汇总

- 单件（单帧）粒度：有效缺陷总数、各类别计数（**恒含 0~3 四个键**，无缺陷时值为 0）、缺陷面积之和（`area_px` 与 `area_ratio` 两个口径）、命中规则列表。
- 批次粒度：样本数、合格数、不合格数、良率、缺陷总数、各类别总数、缺陷面积汇总。
- 良率 `yield_rate = pass_count / (pass_count + fail_count)`；**样本数为 0 时取 `0.0`**（不是 `None`、不除零）。
- 本阶段只输出结构化 `dict`，不绘制统计面板、不做"点击列表定位"（属 GUI 能力，已移出本阶段范围）。

### 4.4 无头输出

- 可视化只返回内存图像 `np.ndarray`；落盘由 `render_to_file` 完成，写入路径由调用方给定（含文件名），父目录不存在时自动创建。
- 批量场景建议文件名包含源标识与帧序号（如 `{源文件名}_frame{frame_index:06d}.jpg`），避免同名覆盖。
- 全链路不调用 `cv2.imshow`/`cv2.namedWindow`/`VideoWriter`，不依赖 `DISPLAY`；产物目录示例为 `reports/visual/`（已在 `.gitignore` 屏蔽）。

## 5. 关键接口落位

### 5.1 接口签名与异常语义

可视化模块（`visualization/`）：

| 签名 | 返回 | 是否可 `None` | 异常语义 |
| --- | --- | --- | --- |
| `render(frame: Frame, detections: List[Detection], verdict: Verdict) -> np.ndarray` | 标注图，`uint8`、BGR、`H×W×3`，与 `frame.image` 同尺寸 | 不可 `None` | `ValueError`：`frame` 非 `Frame`、`image` 非 ndarray/空/非 3 通道、`width/height` 与 `image.shape` 不一致、`detections` 为 `None`/非 list、`verdict` 非 `Verdict`。调用方捕获后按配置错误处理 |
| `render_to_file(frame: Frame, detections: List[Detection], verdict: Verdict, output_path: str) -> str` | 实际写入的文件路径（`str`） | 不可 `None` | `ValueError`：同上或 `output_path` 为空；`OSError`：父目录创建失败或 `cv2.imwrite` 返回 `False`（不静默吞掉写入失败） |

判定模块（`judge/`）：

| 签名 | 返回 | 是否可 `None` | 异常语义 |
| --- | --- | --- | --- |
| `judge(detections: List[Detection], cfg: Optional[dict] = None) -> Verdict` | 结构化判定结果 | 不可 `None` | `ValueError`：`detections` 为 `None`/非 list/含非 `Detection` 元素、`cfg` 非 dict、含未知字段、数值越界、`max_severity` 非 `null` |
| `summarize(verdicts: List[Verdict]) -> dict` | 批次汇总 dict（键见 §4.3） | 不可 `None` | `ValueError`：`verdicts` 为 `None`/非 list/含非 `Verdict` 元素。空列表合法，返回全 0 汇总、`yield_rate=0.0` |

`Verdict` 字段（阶段 7 消费，字段名冻结）：

| 字段 | 类型 | 单位/口径 | 是否可 `None` |
| --- | --- | --- | --- |
| `is_pass` | bool | 合格=`True` | 不可 `None` |
| `reason` | str | 人类可读，命中规则以 `；` 分隔；保证非空 | 不可 `None` |
| `total_count` | int | 有效缺陷数，`≥ 0` | 不可 `None` |
| `class_counts` | `Dict[int, int]` | 键恒为 `0/1/2/3`，缺省类计 0 | 不可 `None` |
| `total_area_px` | int | 有效缺陷 `area_px` 之和 | 不可 `None` |
| `total_area_ratio` | float | 有效缺陷 `area_ratio` 之和，clip 到 `[0,1]` | 不可 `None` |
| `triggered` | `List[str]` | 命中的规则 id（如 `["count:3>0"]`），按 §4.2.1 顺序 | 不可 `None` |

`build_detector` 同层新增的组装入口沿用现有配置风格（`config["judge"]` 下发给 `judge`，不写入检测器）：`judge(detections, config.get("judge"))`、`render(frame, detections, verdict)`。

### 5.2 边界与空值语义

| 情形 | 预期行为（可判定） |
| --- | --- |
| `detections == []` | `judge` 返回 `is_pass=True`、`reason="PASS：未检出有效缺陷"`、各计数为 0；`render` **仍绘制绿色 `PASS` 横幅**，返回原图副本（不修改入参 `frame.image`） |
| `detections is None` | `ValueError`（`None` 不是"无结果"，不得当空列表处理；`None` 仅用于 `InputSource.read()` 的"读尽"语义） |
| `frame is None` / `frame.image is None` | `ValueError` |
| `frame.image.size == 0` / 非 3 通道 / `ndim != 3` | `ValueError` |
| `frame.width/height` 与 `image.shape` 不一致 | `ValueError`（与阶段 3/4 `_validate_frame` 一致） |
| `bbox` 部分越界 | clamp 到图像边界后绘制 |
| `bbox` 完全越界或 `w/h ≤ 0` | 跳过该条绘制、记 `warning`，其余照画，不抛异常 |
| `mask is None` 或 shape 不匹配 | 不填充，照画框；shape 不匹配记 `warning` |
| `verdict` 与 `detections` 自相矛盾（如空列表却传 `is_pass=False`） | 以 `verdict` 为准绘制横幅，不反推、不修正；判定与绘制的唯一权威是 `verdict` |
| 未知 `class_id`（`∉{0,1,2,3}`） | 白色绘制 + `warning`，不抛异常 |
| `output_path` 目录不可写 / 磁盘满 | `OSError`（`cv2.imwrite` 返回 `False` 时主动抛出，不静默） |
| `summarize([])` | 返回全 0 汇总，`yield_rate=0.0`，不抛异常、不除零 |
| 空 `cfg` / `cfg=None` | 全部取 §4.2.2 默认值 |

### 5.3 线程模型与资源生命周期

- **单线程**：可视化与判定均为纯函数式调用，不持有跨帧状态；`Verdict`/`summarize` 无共享可变状态，可被流水线串行调用。
- 无长生命周期外部资源：不打开窗口、不持有 `VideoCapture`/`VideoWriter`/文件句柄；`cv2.imwrite` 单次调用内完成写入并释放句柄。
- 资源所有者：`output_path` 由调用方提供、调用方负责清理；本阶段模块只在 `OSError` 时上抛，不做后台重试或异步写入。
- 因此本阶段不适用「并发与资源生命周期」检查项的常规内容（无窗口/无视频写入器/无线程）；该结论依赖 §3 WBS 第 5 项的**无头约束**，若后续引入实时窗口或 `VideoWriter`，本阶段须按规则 2 升级为完整资源审查。

## 6. 交付物

- 可视化/叠绘模块（`render` / `render_to_file`，无 GUI）。
- 判定模块 + 配置（`judge` / `summarize` / `Verdict`）。

## 7. 阶段要求与验收标准

1. 接口契约与无头约束：`render` 返回 `np.ndarray`，`shape == frame.image.shape`、`dtype == uint8`；空检测列表仍返回同尺寸图并绘制 `PASS`；全程无窗口弹出。
   - 命令：`python3 -m pytest -q tests/test_renderer.py`
   - 通过判据：全部用例通过；且测试进程中 `cv2.getWindowProperty` 不可用/无窗口创建（以用例断言 `mock` 未被调用 `imshow` 为准）。
2. 颜色、线宽、字号符合 §4.1 规范。
   - 命令：`python3 -m pytest -q tests/test_renderer.py -k color`
   - 通过判据：100×100 白底合成图上，四类框的边中点像素 BGR 与 §4.1 表值**完全相等**（容差 0）；200×200 与 2000×2000 下 `thickness` 分别为 1 与 5。
3. 判定规则的配置化与优先级语义正确。
   - 命令：`python3 -m pytest -q tests/test_judge.py`
   - 通过判据：同一组 `detections` 仅改 `cfg.max_count` 时 `is_pass` 由 `False` 翻转为 `True`；`per_class` 与全局规则同时超限时 `triggered` 同时含两类规则 id。
4. PASS/FAIL 全局提示正确。
   - 命令：`python3 -m pytest -q tests/test_judge.py -k pass`，并目检 `reports/visual/` 下产物
   - 通过判据：`judge([]).is_pass is True` 且 `reason.startswith("PASS")`；超阈值样本 `is_pass is False` 且 `reason.startswith("FAIL")`；落盘图上良品为绿色 `PASS`、次品为红色 `FAIL`。
5. 统计数字与原始 `Detection` 严格对应。
   - 命令：`python3 -m pytest -q tests/test_judge.py -k summarize`
   - 通过判据：`total_count == sum(class_counts.values()) == 有效缺陷数`；`yield_rate == pass_count/(pass_count+fail_count)`；空批次 `yield_rate == 0.0`。
6. 三种输入源下无头输出正常（不弹窗、可批量落盘）。
   - 命令：`python3 main.py --config configs/demo.yaml`（图片源）、`python3 main.py --config configs/video_demo.yaml`（视频源）
   - 通过判据：落盘 jpg 数量等于源 `read()` 返回的帧数；进程退出码 0；全程无窗口创建。摄像头源同法验证，设备不可用时该项记「环境不具备」而不判失败。
7. 预留严重度展示位。
   - 命令：构造 `severity="严重"` 的 `Detection` 调 `render`
   - 通过判据：标签文本包含严重度字符串，且不抛异常；`severity=None` 时标签不出现该字段。

## 8. 风险与注意事项

- 坐标原点/坐标系统一（图像像素系，原点左上），避免框错位；绘制前必须 clamp。
- 高分辨率图标注文字易过小，需按 §4.1 公式随分辨率缩放字号/线宽。
- 批量落盘时 jpg 编码与磁盘 I/O 会成为吞吐瓶颈，绘制本身不应再做重复的图像拷贝。

### 特殊风险

- 【可视化模块】在【仅按 bbox 画框而不区分 `area_px` 与 `mask` 口径时】存在【框面积被误读为缺陷实际面积的风险】。
- 【判定模块】在【`per_class` 类内阈值与全局阈值同时生效时】存在【两套阈值合并语义不清导致同批次判定不一致的风险】。
- 【可视化模块】在【以 jpg 有损格式保存标注图时】存在【细边框边缘模糊、影响人工复核判读的风险】。

## 9. 与其他阶段衔接

- 阶段 6 在判定基础上扩展严重度分级与误报分析；本阶段 `max_severity` 恒为 `null`、`severity` 恒为 `None`，展示位已预留。
- 阶段 7 直接复用 `Verdict` 的 `is_pass` / `reason` / `total_count` / `class_counts` / `total_area_ratio` 与 `summarize` 的批次汇总，作为报告数据源（阶段 7 文档中「统计面板数据」的口径即指本阶段结构化汇总）。
- 阶段 8 用可视化产物辅助集成测试与效果复核。
- 后续 Web 端 / ROS2 节点消费本阶段落盘的 jpg 与结构化 `Verdict`；界面开发不在本阶段范围。
