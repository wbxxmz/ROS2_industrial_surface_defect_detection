# 阶段 4：YOLO 模型集成 · 实现技术文档

## 1. 阶段目标

集成 YOLO 系列深度学习检测器，与 OpenCV 路线并列，实现真正的"双算法可切换"，并提升对复杂缺陷的泛化能力。

## 2. 前置条件与依赖

- 依赖阶段 0 的 `Detector` 接口、阶段 2 的帧输入、阶段 3 的对照结论。
- 依赖 PyTorch、YOLO 推理/训练库（如 ultralytics）。
- 需准备缺陷标注数据（阶段 0/3 的样本基础上扩展标注）。

## 3. 工作分解（WBS）

1. 数据标注与格式整理（如 YOLO 标注格式，含四类缺陷）。
2. 数据划分：训练/验证/测试集，处理类别不平衡。
3. 模型训练：选 baseline（YOLOv5/v8/v11），调关键超参。
4. 推理封装：将模型推理输出转换为统一的 `Detection` 结构。
5. 实现 `YoloDetector(Detector)`：`load` 加载权重、`detect` 推理、`release` 释放显存。
6. 接入主流程，与 OpenCV 检测器可配置切换。
7. 评测：mAP / 召回 / 精确率，与阶段 3 对照。

## 4. 关键技术方案

### 4.1 标注与类别

- 类别固定四类 + 可选背景（正常类），类别 id 与阶段 0/3 统一。
- 标注形式：边界框（目标检测）为基础；如需更准面积，后续可扩展为实例分割模型。

### 4.2 推理封装

- 模型输出的 `[class, conf, x, y, w, h]` 映射为 `Detection.bbox / class_name / confidence`。
- 面积由框面积换算或用掩码（若用分割模型）精确计算 `area_px / area_ratio`。
- 通过置信度阈值与 NMS 后处理，抑制重复框与低置信框。

### 4.3 类别不平衡处理

- 训练数据中缺陷样本少：数据增强（旋转/缩放/亮度/合成缺陷）、类别加权、过采样/欠采样。

## 5. 关键接口落位

- `YoloDetector(Detector)`：与 `OpencvDetector` 同构，`detect` 输出 `List[Detection]`。
- `name` 标识（如 `yolov8-n`）、`version` 记录权重版本，供报告溯源。

## 6. 交付物

- YOLO 检测器（可插拔）。
- 训练/推理脚本 + 标注格式说明。
- 评测报告（与 OpenCV 对照）。

## 7. 阶段要求与验收标准

- 同一批样本上 YOLO 与 OpenCV 输出同构 `Detection`，可在配置/界面切换。
- YOLO 对复杂/多样性缺陷的召回优于纯传统方法。
- `release()` 正确释放显存，推理 FPS 满足既定额度。
- 训练、推理、评测流程可复现（保存超参与随机种子）。

## 8. 风险与注意事项

- 缺陷样本稀缺是本路线最大瓶颈，先做数据增强与预训练权重迁移。
- GPU 显存受限时选小模型（n/s 量级）或量化。
- 严格保证类别 id 与 OpenCV 一致，否则报告/统计错乱。

## 9. 与其他阶段衔接

- 阶段 5 可视化同时支持两种检测器输出。
- 阶段 6 小样本/无监督能力可在本模块基础上扩展。
- 阶段 6 的算法对比中 YOLO 作为深度学习路线的代表参评。
