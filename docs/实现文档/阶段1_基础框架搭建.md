# 阶段 1：基础框架搭建 · 实现技术文档

## 1. 阶段目标

搭起可运行的工程骨架，跑通一条"加载占位图 → 检测(空实现) → 输出空结果"的端到端流程，为后续所有算法与输入源提供落地容器。

## 2. 前置条件与依赖

- 依赖阶段 0 的接口契约（`Detection` / `Detector` / `InputSource`）。
- 已确定项目语言与依赖管理方式。

## 3. 工作分解（WBS）

1. 建立工程目录结构（分层：`core` 接口、`inputs`、`detectors`、`pipeline`、`ui`、`report`、`utils`）。
2. 依赖管理：生成依赖清单（如 `requirements.txt`/`pyproject.toml`）并锁定基础依赖（OpenCV、NumPy）。
3. 配置管理：统一配置加载（YAML/JSON），含算法选择、输入源参数、阈值等。
4. 日志系统：分级日志 + 运行日志落盘（日志级别、落盘路径、格式 TBD-阶段 2 前定）。
5. 异常处理：定义 4 个自定义异常（`DetectorLoadError`、`DetectorInferenceError`、`SourceOpenError`、`InputSourceError`，与阶段 0 §5.4 一致）+ 上层统一捕获与可读报错提示。
6. 实现 `Detector`、`InputSource` 抽象基类（空实现/抛 NotImplemented）。
7. 实现流水线骨架：`采集 → 预处理(占位) → 检测(空实现) → 后处理(占位) → 输出`。
8. 单元测试骨架 + 一个冒烟测试。

## 4. 关键技术方案

### 4.1 目录结构（示意）

```
project/
├─ core/            # 接口与数据结构：Detection、Detector、InputSource
├─ inputs/          # 阶段2：图片/视频/摄像头
├─ detectors/       # 阶段3/4：opencv / yolo
├─ pipeline/        # 流水线编排
├─ ui/              # 阶段5：可视化
├─ report/          # 阶段7：报告
├─ configs/         # 配置样例
├─ tests/           # 单元/冒烟测试
└─ utils/           # 日志、配置、异常
```

### 4.2 配置驱动

- 检测器、输入源通过配置文件（而非硬编码）选择，为后续"换算法不改代码"打底。
- 配置含：`input.type`、`detector.type`、`detector.threshold`、`report` 等字段（以上为占位示例，具体字段名与结构 TBD-阶段 2 前定，不设默认值）。

### 4.3 流水线骨架

流水线各环节做成独立可替换的函数/类，阶段 2–5 逐个"填空"：

`帧 → 预处理 → 检测 → 后处理 → 结果列表`

- 预处理、后处理先用直通（pass-through）占位实现。
- 环节数据契约（与下游对齐）：采集输出 `Frame`（阶段 2 帧对象，字段见阶段 0 §5.4.4）；检测输出 `List[Detection]`（阶段 3/4）；预处理 `Frame -> Frame`、后处理 `List[Detection] -> List[Detection]` 直通时不改类型。

## 5. 关键接口落位

- `Detector` 基类（空壳，签名/返回值/异常与阶段 0 §5.4.2 逐字一致，不得改动）：
  - `load(cfg)`：cfg: dict；字段 TBD-阶段 2；返回 None；失败抛 `DetectorLoadError`，由调用方捕获（空壳抛 `NotImplementedError`）。
  - `detect(frame)`：frame: Frame；返回 `List[Detection]`；无缺陷返回 `[]`，不返回 None；输入非法抛 `ValueError`、推理异常抛 `DetectorInferenceError`（空壳抛 `NotImplementedError`）。
  - `name`：str 属性，不可 None。
  - `version`：str 属性，格式 TBD-阶段 1，不可 None。
  - `release()`：返回 None；应幂等；细节 TBD-阶段 2。
- `InputSource` 基类（空壳，与阶段 0 §5.4.3 一致，不得改动）：
  - `open(source_cfg)`：source_cfg: dict；字段 TBD-阶段 2；返回 None；失败抛 `SourceOpenError`，由调用方捕获（空壳抛 `NotImplementedError`）。
  - `read()`：返回 Frame 或 None；None 只表示读尽；出错抛 `InputSourceError`（空壳抛 `NotImplementedError`）。
  - `close()`：返回 None；应幂等；细节 TBD-阶段 2。
- 冒烟测试调用一个 `DummyDetector`，返回空 `Detection[]`，验证流水线能走通。
- 基类方法体抛 `NotImplementedError` 表示未实现；子类覆盖后按阶段 0 契约抛 `DetectorLoadError` / `SourceOpenError` / `DetectorInferenceError` / `InputSourceError`，不得把 `NotImplementedError` 作为契约异常。

## 6. 交付物

- 可启动的工程骨架 + 依赖清单。
- 空实现的检测流水线。
- 冒烟测试通过记录。

## 7. 阶段要求与验收标准

- [ ] `Detector`/`InputSource` 基类与阶段 0 §5.4 契约逐字一致：方法名、参数、返回类型、None 语义、异常语义无偏离；空壳方法抛 `NotImplementedError`，不擅自改签名。
- [ ] 4 个自定义异常 `DetectorLoadError`、`DetectorInferenceError`、`SourceOpenError`、`InputSourceError` 已在异常处理处定义，任一异常都有可读报错、日志能定位出错环节。
- [ ] 占位流水线输入输出对齐：采集输出 `Frame`、检测输出 `List[Detection]`、预处理/后处理直通不改类型。
- [ ] `python main.py --config demo.yaml` 能启动并跑完整条流水线，不崩溃。
- [ ] 冒烟测试（`pytest`）一键执行通过。
- [ ] 本阶段未引入插件注册器、事件总线、过度配置层等当前不需要的扩展点。

## 8. 风险与注意事项

- 抽象基类此时不宜过度设计，留最少方法即可，避免后续被束缚。
- 配置/日志结构本节定好，阶段 3、4 大量调参会依赖，勿临时返工。
- 别在本阶段引入具体算法，保持骨架纯净，便于阶段间隔离排错。
- 审查检查项 2.2 异常与边界：不适用——本阶段为单线程骨架、无实际输入源，空帧/损坏文件等边界处理由阶段 2 实现，本阶段不编造边界情形。
- 审查检查项 2.3 并发与资源生命周期：不适用——本阶段无并发、无外部资源（文件/摄像头/模型句柄），资源生命周期由阶段 2/4 实现，本阶段不编造资源语义。
