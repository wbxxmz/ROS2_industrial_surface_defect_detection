# 阶段 7：质检报告生成 · 实现技术文档

## 1. 阶段目标

输出可交付、可归档的质检报告，把检测结果沉淀为结构化文档（PDF / Excel，可选 Word），支持批量检测自动汇总。采用**无头架构**：仅按配置路径直接落盘，不启动 GUI 预览、不弹窗、不实时渲染窗口（后续 Web 交付时再由上层读取报告文件，见阶段 9）。

## 2. 前置条件与依赖

- 依赖阶段 5 的 `Verdict` 与 `summarize()` 汇总输出（本报告的唯一权威口径来源）。
- 依赖阶段 0 的 `Detection` 字段（缺陷明细字段由其决定）。
- 依赖阶段 5 可视化模块落盘的标注图文件路径（每个样本的 `image_path`）。
- 可选依赖阶段 6 的严重度分级（`Detection.severity` / `Verdict.max_severity`）、算法对比结果。

**运行时依赖（按导出格式按需安装，无需全量）**

| 依赖库 | 用途 | 必装与否 |
| --- | --- | --- |
| `reportlab` | PDF 导出 | 生成 PDF 时必装 |
| `openpyxl` | Excel(.xlsx) 导出 | 生成 Excel 时必装 |
| `matplotlib` | 缺陷分布/面积统计图（PNG，嵌入报告） | 报告含统计图时必装 |
| `python-docx` | Word 导出 | 可选 |

- 上述库通过其**文件级 API 直接落盘**（如 `canvas.save()`、`Workbook().save()`、`savefig()`），全程无 GUI 依赖，符合无头架构。
- PDF 中文渲染需显式注册一份 TTF 中文字体（如系统 `NotoSansCJK` 或项目自带的字体文件），否则正文中文会乱码。

## 3. 工作分解（WBS）

1. 报告模板设计：检测概览、缺陷明细表、良率统计、缺陷分布图。
2. 数据组装：从 `Verdict` / `Detection` / `summarize()` 结果抽取报告所需字段。
3. 图表生成：缺陷分布、按类别的面积/数量统计等。
4. 导出实现：PDF（reportlab）、Excel（openpyxl）两种基准格式；Word（python-docx）为可选。
5. 批量汇总：批量检测后自动汇总生成总报告。
6. 溯源信息：样本标识、算法名称/版本、参数、时间戳计入报告。

## 4. 关键技术方案

### 4.1 报告内容结构

- **概要页**：检测批次、样本总数、合格/不合格数、良率、算法版本、最高严重度汇总。
- **缺陷明细表**：逐样本或逐缺陷列出类别、bbox/位置、面积占比、置信度、（可选）严重度。
- **统计图**：缺陷类别分布柱图、面积分布、良率趋势。
- **溯源尾注**：算法与参数、检测时间、样本来源。

### 4.2 导出技术

- 图表：matplotlib 生成 PNG 嵌入报告（`savefig` 落盘后 `plt.close` 释放，见 §4.5）。
- PDF：`reportlab`；Excel：`openpyxl`；可选 Word：`python-docx`。
- 模板与数据分离：`数据组装 → 渲染导出` 两段，便于日后新增报告样式而不改数据逻辑。

### 4.3 输入契约与数据对齐（唯一口径）

报告字段只从 `Detection` / `Verdict` / `summarize()` 读取，杜绝"人工手填"造成口径漂移。

**判定结果消费字段清单（来自 `Verdict` + `summarize()`）**

| 字段 | 类型 | 单位/展示格式 | 来源 |
| --- | --- | --- | --- |
| `is_pass` | bool | 合格 / 不合格 | `Verdict` |
| `reason` | str | 原文 | `Verdict` |
| `total_count` | int | 个 | `Verdict` |
| `class_counts` | Dict[int,int] | 键恒 0/1/2/3 | `Verdict` |
| `total_area_px` | int | 像素² | `Verdict` |
| `total_area_ratio` | float | 0~1，展示为百分比（×100，2 位小数） | `Verdict` |
| `triggered` | List[str] | 原文规则 id | `Verdict` |
| `max_severity` | Optional[int] | `{None,0,1,2}` | `Verdict`（阶段 6 §4.1.5 新增） |

- `max_severity=None` 表示无有效缺陷 / 全部未分级 / 分级关闭，报告中按**"未分级"**展示，**不得当作 0**。
- 批次级汇总（`sample_count` / `pass_count` / `fail_count` / `yield_rate` / `total_count` / `class_counts` / `total_area_px` / `total_area_ratio`）由 `summarize()`（阶段 5 §4.3）在报告模块内部一次性求得，报告**不重复计算**，保证与统计面板逐字段一致。
- `yield_rate` 为 0~1，展示为百分比；空批次恒为 0.0（不除零）。

**缺陷明细字段（来自 `Detection`）**

| 字段 | 类型 | 单位/展示格式 |
| --- | --- | --- |
| `class_name` / `class_id` | str / int | 类别名（中文）/ 稳定 id |
| `bbox` | tuple[x,y,w,h] | 像素，左上原点 |
| `area_px` | int | 像素² |
| `area_ratio` | float | 0~1，展示为百分比（×100，2 位小数） |
| `confidence` | float | 0~1，2 位小数 |
| `severity` | Optional[int] | `{None,0,1,2}` |

- 缺陷明细中的严重度直接取 `Detection.severity`（`{None,0,1,2}`）；报告正文可用中文名（轻度/中度/重度），**图中标注仍用 ASCII `S0/S1/S2`**（与阶段 5/6 渲染规范一致，避免 cv2 乱码）。

### 4.4 异常语义与边界回退（唯一口径）

| 情形 | 预期行为（可判定，不含"酌情"） |
| --- | --- |
| `batch` 为 `None` 或非 `list` | `ValueError`（与阶段 5 `summarize()` 输入校验一致） |
| `batch` 为空列表 `[]` | `ValueError`，**不静默失败、不生成空报告文件** |
| `batch` 含非 dict 元素、或某元素缺失 `verdict`/`source`/`detections` 必填键 | `ValueError` |
| 目标 `output_path` 所在目录无写权限、目录不存在且无法创建、磁盘空间不足 | `OSError`（由 reportlab/openpyxl 底层异常原样上抛，报告模块**不吞**）；报告模块本身不新建权限/降级路径 |
| `image_path` 为 `None` 或指向文件不存在（可视化环节漏保存） | **优雅降级**：该样本图位渲染为占位（浅灰背景 + 文字提示"图片缺失/N/A"），**不抛异常、不中断报告**，并记 `warning` 日志；缺陷明细表仍照常输出 |
| 无有效缺陷（`total_count == 0`） | 明细表输出空表（表头保留），概览良率、统计图照常生成 |

### 4.5 并发与资源生命周期

- **线程模型：单线程**。同一时刻只写一份报告，不声明线程安全；不提供多线程并发写同一文件的能力。
- 文件句柄用上下文管理器（`with`）/ 或 `save()` 后立即释放，确保**异常路径也能关闭**：
  - `reportlab`：`with canvas.Canvas(...) as c:`，或 `c.save()` 后 `c` 不再被引用；
  - `openpyxl`：构造 `Workbook` → `wb.save(path)`（内部自行关闭写入流）；
  - matplotlib：`fig.savefig(...)` 后 `plt.close(fig)`，释放 Figure 与画布内存。
- **批量处理**：逐份 `build()` → 完成即释放（文件句柄、Figure、中间数据）→ 再 `build()` 下一份；**不持有全部报告的中间对象**，避免文件句柄泄漏与内存峰值累积。
- 资源所有者：`ReportBuilder.build()` 内部创建的（文件句柄/Figure）由 `build()` 自身负责关闭；调用方只负责传入数据与接收返回的落盘 `Path`，不承担释放。

## 5. 关键接口落位

对外公开接口唯一入口 `ReportBuilder`（阶段内部「数据组装 → 渲染导出」分离，导出器/组装器为私有实现，均不属于对外契约）：

| 签名 | 返回 | 是否可 `None` | 异常语义 |
| --- | --- | --- | --- |
| `ReportBuilder.build(batch: List[dict], cfg: dict) -> Path` | 报告文件落盘路径 | 不可 `None` | `ValueError`：`batch` 为 `None`/非 list、`batch` 空、元素非 dict 或缺失必填键；`OSError`：目标目录无写权限 / 无法创建 / 磁盘空间不足（底层异常原样上抛） |

- `batch` 每元素为单样本记录（`dict`，必填键）：
  - `source`：`str`，样本标识（文件名主干 / 帧号）；
  - `verdict`：`Verdict`（阶段 5 §5.1）；
  - `detections`：`List[Detection]`（阶段 0 §5.4.1，该样本有效缺陷明细）；
  - `image_path`：`Optional[str]`，可视化落盘路径；`None` 表示该样本无图（见 §4.4 降级）。
- `cfg` 必填键：`output_path`（`str`）、`format`（`"pdf"` / `"xlsx"`，可选 `"docx"`）；可选键：`title`、`algorithm_name`/`algorithm_version`、`params`（溯源尾注）、`font_path`（PDF 中文字体）。
- 组装器与导出器分离：`数据组装（读取 batch → 汇总） → 渲染导出（套模板写文件）`。

## 6. 交付物

- 报告生成模块（对外入口 `ReportBuilder`）+ 模板。
- PDF（reportlab）、Excel（openpyxl）两种基准格式导出能力；Word（python-docx）为可选扩展。
- 批量汇总功能。
- 报告模块单元测试（`tests/test_report.py`）：字段一致性、空批次异常、无写权限异常、图片缺失降级。

## 7. 阶段要求与验收标准

通用要求：报告信息真实、可追溯（含样本标识、算法版本、参数、时间）；报告与统计面板数据一致，抽样核对无出入。

1. PDF / Excel 可正确落盘。

   - 命令：`python3 -c "from report import ReportBuilder; ...build(batch, cfg)"; ls -l <output_path>`
   - 通过判据：返回 `Path`，文件存在且大小 > 0。

2. 报告字段与 `summarize()` / `Verdict` 逐字段一致（含 `max_severity`）。

   - 命令：`python3 -m pytest -q tests/test_report.py -k consistency`
   - 通过判据：断言报告内 `样本总数 / 良率 / 各类别计数 / total_area_ratio / max_severity` 与 `summarize()` 输出相等；`max_severity=None` 展示为"未分级"而非 0。

3. 空批次与非法输入报错、不静默失败。

   - 命令：`python3 -m pytest -q tests/test_report.py -k empty`
   - 通过判据：`pytest.raises(ValueError)`，且目标路径**不产生**报告文件。

4. 目标路径无写权限抛 `OSError`。

   - 命令：`python3 -m pytest -q tests/test_report.py -k permission`
   - 通过判据：`pytest.raises(OSError)`（对只读目录写）。

5. 图片缺失优雅降级。

   - 命令：`python3 -m pytest -q tests/test_report.py -k missing_image`
   - 通过判据：`image_path=None` 或不存在时仍生成报告（返回 `Path`、文件存在），缺陷明细表照常输出，日志含 `warning`。

6. 批量汇总 + 资源释放。

   - 命令：`python3 -m pytest -q tests/test_report.py -k batch_release`
   - 通过判据：连续对 ≥N 份样本 build，进程文件句柄数不随批次数单调增长（每份 build 后回落），无 `ResourceWarning`。

## 8. 风险与注意事项

- 报告字段若与 `Detection` / `Verdict` 未严格绑定，容易出现"图和表对不上"（见 §4.3 单一口径约束）。
- 大数据量时导出需控制内存与渲染时长（分批/流式写，见 §4.5）。
- 中文/字体渲染在 PDF 中易出乱码，需配置中文字体（见 §4.2 / §5 `cfg.font_path`）。

**特殊风险（仅点名，不在此展开）**

- 【报告模块】在「PDF 输出」存在中文字体缺失导致的乱码风险。
- 【报告模块】在「缺陷明细表与统计概览」存在字段口径不一致（图/表对不上）风险。

## 9. 与其他阶段衔接

- 阶段 5 的 `Verdict` 与 `summarize()` 汇总输出是报告的输入来源（别名"统计面板数据"即指该结构化统计输出，非 GUI 面板；本报告为无头架构）。
- 阶段 6 的严重度分级（`Detection.severity` / `Verdict.max_severity`）、算法对比结果可纳入报告。
- 阶段 9 交付时，报告是"全流程跑通"的最终产物之一，由 Web 层读取本阶段落盘的 PDF/Excel/PNG 文件，本阶段不提供预览窗口。
