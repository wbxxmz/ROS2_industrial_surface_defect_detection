# 阶段 9：部署与交付 · 实现技术文档

## 1. 阶段目标

交付一个"别人克隆后能独立上手"的通用质检工具，完成一键启动、文档与验收，让新用户在**全新环境**下走通"导入数据 → 选算法 → 出报告"全流程。本阶段延续无头架构：交付形态为 **CLI + 报告落盘**（无 GUI），Web / ROS2 仅作为后续节点预留接口，不在本阶段实现。

## 2. 前置条件与依赖

- 依赖阶段 2–8 全部完成并通过集成测试。
- 运行环境：Python ≥ 3.10；Linux 原生环境（不使用模拟器/非 Linux 软件）。
- 必装依赖：`opencv-python`、`numpy`、`reportlab`、`openpyxl`、`matplotlib`、`psutil`、`pyyaml`。
- 可选依赖：`torch`（含 `ultralytics`）—— 仅 YOLO 路线需要，缺失时 OpenCV 路线仍可运行。
- 模型权重 `best.pt`（约 52 MB）**不入库**（见 §4.3 / §8），需按 §4.3 获取。

## 3. 工作分解（WBS）

1. 一键启动脚本：`run_demo.sh`，新用户克隆后一条命令跑通（§4.2）。
2. 环境说明：Python 版本、依赖安装、可选 GPU 环境配置、无 GPU 兜底（§2 / §4.4）。
3. README：环境要求、安装步骤、三种运行方式（OpenCV / YOLO / 压测）、目录结构、性能基线表、License（§4.3）。
4. 权重分发：`best.pt` 获取方式（训练脚本复现或外部下载），仓库不含权重（§4.3）。
5. 算法接入说明：如何基于 `Detector` 接口新增一种算法（§5）。
6. 交付验收：全新环境跑通样例数据全流程，产出报告（§7）。

## 4. 关键技术方案

### 4.1 打包与部署形态

- **本阶段交付形态**：CLI 入口（`main.py`）+ 一键脚本（`run_demo.sh`）+ 配置驱动（`configs/*.yaml`）。
- 接口预留：Web（FastAPI）/ ROS2 节点作为后续阶段接入点，本阶段只预留、不实现；桌面 GUI 因无头架构原则（阶段 5 起）而不提供。
- 依赖收敛：`requirements.txt` 列全依赖；模型权重单独分发（体积大不入库）。

### 4.2 一键启动（run_demo.sh）

- 脚本目标：新用户 `git clone` 后 `bash run_demo.sh` 即可跑通 OpenCV 全流程并产出报告。
- **依赖缺失必须给出可读提示而非 traceback**（硬性要求）：脚本运行前做环境自检，逐项检查 `python3`、`opencv`、`numpy`、`reportlab`、`openpyxl`、`matplotlib`、`psutil` 是否可用；缺失时打印形如「缺少依赖 opencv-python，请执行 `pip install -r requirements.txt`」的中文提示并以非零码退出，**不打印裸 Python traceback**。
- **设备自检**：脚本探测 CUDA；存在 GPU 则提示可用 YOLO 路线，不存在则提示走 OpenCV 路线（回退选择见 §4.4）。
- 权重检查：YOLO 路线启动前检查 `best.pt`，缺失时按 §4.3 给出获取指引后退出（不静默跳过 YOLO）。

### 4.3 文档体系与权重分发

README 必须完整覆盖以下七项（缺一即不合格）：

1. **环境要求**：Python ≥ 3.10、Linux、必装/可选依赖清单。
2. **安装步骤**：`pip install -r requirements.txt`（含可选的 GPU/CUDA 版 torch 安装说明）。
3. **三种运行方式**：
   - OpenCV 路线：`python3 main.py --config configs/demo.yaml`
   - YOLO 路线：`python3 main.py --config configs/yolo_demo.yaml`（需 `best.pt`）
   - 压测：`python3 scripts/benchmark.py --config configs/yolo_demo.yaml --input tests/data/stress_images --limit 30`
4. **目录结构**：项目根目录关键路径说明（`core/` `detectors/` `configs/` `inputs/` `judge/` `visualization/` `report/` `scripts/` `tests/` `reports/`）。
5. **性能基线表**：引用阶段 8 基准结果（OpenCV ~270 FPS / YOLOv8m ~66 FPS 检测，标注 CPU/GPU 环境）。
6. **License**。

**权重分发**：`best.pt`（52 MB）不入库（已在 `.gitignore` 忽略 `*.pt`）。README 须写清两条获取路径，二者缺一不可：
- 训练脚本复现：`python3 scripts/train_yolo.py`（或项目训练脚本，基于 NEU-DET 自训练）；
- 外部下载：给出可用的下载地址与放置位置（项目根目录）。

### 4.4 设备回退语义（写死）

- `yolo_demo.yaml` 中 `device: cuda` 且当前环境 `torch.cuda.is_available() == False` 时，**必须明确抛出 `DetectorLoadError`，不得静默回退 CPU**（与阶段 4 §4.4 / §5.1 现有实现一致）。
- 无 GPU 用户的两条既定路径（任一即可）：改用 `configs/demo.yaml`（OpenCV 路线，`device` 不参与）；或自行把 `yolo_demo.yaml` 的 `device` 改为 `cpu` 后走 YOLO（性能下降，属显式选择）。
- 此语义不新增回退逻辑，只做「报错 vs 回退」的最终裁定并在 README 前置说明。

## 5. 关键接口落位

| 入口 | 契约 |
| --- | --- |
| `bash run_demo.sh` | 无参；退出码 0=OpenCV 全流程跑通并生成报告；非 0=环境自检失败（依赖缺失/权重缺失/设备不支持），stderr 打印可读中文提示，不裸抛 traceback |
| 新算法接入 | 继承阶段 0 §5.4.2 的 `Detector`（`name` / `version` / `load(cfg)` / `detect(frame)` / `release()`），在 `pipeline.build_detector` 的 `detector.type` 分支注册；`load` 失败抛 `DetectorLoadError`，`detect` 失败抛 `DetectorInferenceError`（不新增类/接口） |

- `run_demo.sh` 是对既有 `main.py --config configs/demo.yaml` 的薄封装 + 环境自检，不复制业务逻辑。
- 新算法接入文档举一个最小示例（如 `DummyDetector`）说明继承与注册步骤。

## 7. 阶段要求与验收标准

1. 一键启动跑通（全新环境）。

   - 命令：`bash run_demo.sh`
   - 通过判据：退出码 0，`reports/` 生成报告；触发依赖缺失时打印可读提示、无裸 traceback。

2. 三种运行方式均可执行。

   - 命令：§4.3 列出的三条命令分别执行
   - 通过判据：OpenCV / YOLO / 压测各自退出码 0 并产出对应报告或指标。

3. 权重不入库 + 获取方式齐全。

   - 命令：`git ls-files | grep -E '\.pt$'`（应为空）+ `git check-ignore best.pt`
   - 通过判据：仓库不含 `.pt`；README 同时给出训练复现 + 外部下载两条获取路径。

4. 无 GPU 时 YOLO 明确报错、不回退。

   - 命令：无 CUDA 环境（或 `device: cuda` 且 `torch.cuda.is_available()==False`）跑 YOLO 路线
   - 通过判据：抛出 `DetectorLoadError`（报错信息含「不静默回退」）、退出码非 0；同一环境走 OpenCV 路线可正常出报告。

5. 新算法接入可按指南复现。

   - 命令：按 §5 示例新增一个检测器并注册后跑通
   - 通过判据：能通过 `detector.type` 路由到新检测器并完成 `load/detect/release` 全周期。

6. 交付物齐全。

   - 命令：核对 §6 六项交付物存在
   - 通过判据：`run_demo.sh`、`README.md`（含七项）、`requirements.txt`、样例数据、权重获取说明、算法接入指南均落盘。

## 8. 风险与注意事项

- 模型权重大文件不入代码仓库，需说明分发与存放位置（§4.3）。
- 文档要随版本更新，避免"文档与程序不一致"。
- 部署环境差异（有无 GPU）需在文档中明确说明（§4.4）。
- 依赖版本差异大，需锁定关键依赖版本或给出兼容区间。

**特殊风险（仅点名，不在此展开）**

- 【run_demo.sh】在「依赖缺失分支」存在只报缺依赖但未区分「自动安装 / 手动安装」，导致新用户无法继续的风险。
- 【权重分发】在「best.pt 不入库 + 外部下载」存在下载源失效时无法复现训练、进而一键演示跑不通的风险。
- 【设备回退】在「yolo_demo.yaml 写死 device:cuda」存在无 GPU 用户首跑即 `DetectorLoadError`、且 README 未前置说明的风险。
