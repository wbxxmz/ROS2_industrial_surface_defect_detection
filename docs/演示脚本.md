# 工业表面缺陷检测平台 · 演示脚本

> 适用版本：v1.2.0（CLI 批量 + 双算法对比页 + Web 演示服务）
> 演示目标：在 8 分钟内说明「双算法为什么必要」「配置驱动怎么落地」「工程化程度如何」

---

## 0. 演示前准备

### 0.1 环境自检

```bash
cd demo_OpenCv_picture

python3 --version                                    # 需 ≥ 3.10
python3 -c "import cv2, numpy, reportlab, openpyxl"  # 核心依赖
ls best.pt                                           # YOLO 权重（约 52 MB，不入库）
ls test_picture | wc -l                              # 演示集 15 张
```

缺依赖：`pip install -r requirements.txt`；YOLO 另需 `pip install torch ultralytics`。

### 0.2 预热（关键）

模型是懒加载，首个请求要等 3~5 秒。演示前先跑一次，把权重读进内存：

```bash
python3 main.py --config configs/html_yolo_demo.yaml >/dev/null 2>&1
```

### 0.3 启动 Web 服务

另开一个终端，保持不关：

```bash
cd demo_OpenCv_picture
uvicorn web.app:create_app --factory --host 127.0.0.1 --port 8000
```

### 0.4 打开两个浏览器标签页

| 标签 | 地址 | 用途 |
| --- | --- | --- |
| 1 | `http://127.0.0.1:8000` | 拖拽上传演示 |
| 2 | `file:///绝对路径/demo_OpenCv_picture/reports/algorithm_comparison.html` | 双算法三栏对比 |

> 对比页若不存在，先执行 `python3 scripts/compare_html.py`。
> 另外两份批量 HTML 报告的生成与打开方式见 §0.6。

### 0.5 素材清单（放在手边）

| 图片 | 预期结论 | 演示意图 |
| --- | --- | --- |
| `test_picture/crazing_98.jpg` | OpenCV = PASS，YOLO = FAIL(S2) | 单算法漏检、双算法互补 |
| `test_picture/inclusion_174.jpg` | YOLO 检出 2 条 `inclusion` | 正常检出 + 注意力图 |
| 任意一张干净图 | PASS | 空检测仍出 PASS 横幅 |
| 任意一个 `.txt` 文件 | 422 结构化错误 | 输入边界与异常语义 |

### 0.6 本地 HTML 怎么在浏览器打开

生成的三份 HTML 均为**自包含**文件（图片 base64 内嵌、CSS 内联），**不需要启动任何服务器**，双击或 `file://` 直接打开，断网也能正常显示。

| HTML 文件 | 生成命令 | 打开命令 |
| --- | --- | --- |
| `reports/quality_report.html`（OpenCV 批量） | `python3 main.py --config configs/html_demo.yaml` | `xdg-open reports/quality_report.html` |
| `reports/quality_report_yolo.html`（YOLO 批量 + 注意力图） | `python3 main.py --config configs/html_yolo_demo.yaml` | `xdg-open reports/quality_report_yolo.html` |
| `reports/algorithm_comparison.html`（双算法三栏） | `python3 scripts/compare_html.py` | `xdg-open reports/algorithm_comparison.html` |

浏览器地址栏等价写法（不受桌面环境影响）：

```text
file:///绝对路径/demo_OpenCv_picture/reports/quality_report.html
file:///绝对路径/demo_OpenCv_picture/reports/quality_report_yolo.html
file:///绝对路径/demo_OpenCv_picture/reports/algorithm_comparison.html
```

备用方式：`xdg-open` 无响应时用 `firefox <文件>` / `google-chrome <文件>`；或在 IDE 中右键 HTML → `Open Preview` / `Live Server`。

两点提醒：

- `reports/` 被 `.gitignore` 忽略，新克隆的环境里不会自带这三份文件，先执行上表的生成命令；
- Web 端单样本报告 `reports/web/<request_id>_report.html` 文件名带随机 id，无法预先打开，演示时从页面「下载 HTML 报告」按钮获取。

> 演示前建议先执行一次 `ls -lh reports/*.html`，确认三份文件都在且非空。

## 1. 演示流程（约 8 分钟）

### 第一段：开场定位（约 30 秒）

**口头**：

> 这是一个工业产品表面缺陷检测平台，传统 OpenCV 与 YOLOv8m 双算法并存，配置驱动、无头架构，既能 CLI 批量出报告，也能 Web 单张交互。核心目标是解决单算法漏检不可接受的问题。

**顺着目录讲一句分层**：

```text
core/          强类型契约（Detection / Frame / Verdict / Detector 抽象）
detectors/     两种实现：OpenCV 传统算子、YOLOv8m
pipeline/      统一流水线：输入 → 检测 → 分级 → 判定 → 落盘
judge/ severity/  业务规则（全部来自 YAML，不写死）
report/ visualization/   PDF / Excel / HTML 报告 + 标注图 + 热力图
web/           FastAPI 演示服务（单张上传）
```

### 第二段：CLI 批量跑通（约 1 分钟）

```bash
./run_demo.sh opencv
```

**讲**：

- 终端出现 `[报告] reports/quality_report.pdf`；
- 打开 PDF，依次指 KPI（样本数 / 良率 / 缺陷数）、缺陷明细表（注意「是否计入判定」列）、标注图；
- 说明「阈值全在 `configs/demo.yaml`，换产线只改配置」。

### 第三段：只换配置换算法（约 1 分钟）

```bash
./run_demo.sh yolo
```

**讲**：

> 同一套流水线、同一份判定代码，只改了 `detector.type` 和权重文件。

**对比两份 PDF**：检出率 40% → 93.3%，良率随之变化。强调「没有改任何业务代码，体现配置驱动」。

### 第四段：双算法对比页（约 2 分钟，最出彩）

切到浏览器标签 2，翻到 `crazing_98` 卡片，按三栏讲：

| 栏位 | 内容 | 话术 |
| --- | --- | --- |
| 左 | OpenCV 标注图 | 判 PASS —— 传统算子漏检 |
| 中 | YOLO 标注图 | 判 FAIL（S2 重度）—— 深度学习补上 |
| 右 | EigenCAM 注意力热图 | 模型关注区域与缺陷位置吻合 |

**收尾一句**：

> 这就是做双算法的理由：OpenCV 漏检率 60%、YOLO 漏检率 13.3%，并集检出率 90%。注意力图只做解释、不参与判定，避免可解释性反过来影响结论。

### 第五段：Web 交互（约 3 分钟）

1. 拖 `inclusion_174.jpg` → 红色 FAIL 徽标、明细表 2 条 `inclusion`、右侧注意力热力图；
2. 点「下载 HTML 报告」→ 断网双击仍可打开（图片 base64 内嵌，无外链）；
3. 拖一张干净图 → 绿色 PASS，明细表为空但 PASS 横幅仍在；
4. 拖 `.txt` → 返回 422 结构化错误，页面不崩、不露堆栈。

**可选加演**：说明换算法只需换配置启动

```bash
DEFECT_WEB_CONFIG=configs/html_demo.yaml uvicorn web.app:create_app --factory --port 8001
```

### 第六段：收尾（约 30 秒）

- **工程**：契约先行、阈值全配置化、异常语义化（`DetectorLoadError` / `DetectorInferenceError` / `SourceOpenError`）、`251 passed, 1 skipped`、版本打标 v1.0.0 / v1.1.0 / v1.2.0；
- **性能**：OpenCV 平均 3.7 ms/张、YOLOv8m 15.0 ms/张，端到端 ≥ 20 FPS；
- **可扩展**：级联检测器已列入 V1.5 规划。

```text
│  ├─ crazing_98.jpg
│  ├─ attention_crazing_98.jpg           # EigenCAM 注意力热图（仅 YOLO）
│  ├─ density_inclusion_174.jpg          # 密度热力图（临时脚本产物）
│  └─ compare/                           # 对比页三件套
│     └─ crazing_98__opencv.jpg / __yolo.jpg / __attention.jpg
└─ web/                                  # Web 每次上传的产物，按 request_id 命名
   ├─ 1529f4aa0f9b.jpg                   # 标注图
   ├─ attention_1529f4aa0f9b.jpg         # 注意力图
   ├─ 1529f4aa0f9b_report.html           # 单样本 HTML 报告
   └─ 1529f4aa0f9b_report.pdf            # 单样本 PDF 报告
```

两个容易忽略的点：

- 报告内嵌的类别分布柱状图是临时文件 `*_class_chart.png`，转 base64 / 图片对象后立即删除，不会在 `reports/` 残留；
- `reports/` 整体被 `.gitignore` 忽略，需要长期留档的图要复制到 `docs/images/`（已入库 3 张演示图，合计约 33 KB）。

## 4. 常见问题应对

| 现场现象 | 原因 | 处理 |
| --- | --- | --- |
| 首个上传请求卡 3~5 秒 | 模型懒加载 | 已按 §0.2 预热；或口头说明「首次加载权重」 |
| `CUDA out of memory` | 显存不足 | 把配置里 `device: cuda` 改 `cpu` 后重跑 |
| 8000 端口被占用 | 端口冲突 | 换 `--port 8001`，同步改浏览器地址 |
| 页面只有 YOLO 结果 | 默认配置为 YOLO | 用 `DEFECT_WEB_CONFIG=configs/html_demo.yaml` 启动 |
| 报告里图片显示「图片缺失」 | 未先跑检测 | 先跑一次对应配置，生成 `reports/visual/*.jpg` |
| 对比页空白或 404 | 页面未生成 | `python3 scripts/compare_html.py` |
| `xdg-open` 打不开 HTML | 桌面环境 / 默认程序缺失 | 改用 `firefox <文件>`，或在地址栏粘贴 `file:///...` 路径 |
| 打开 HTML 后图片空白 | 报告引用的标注图被删 | 重跑对应配置生成 `reports/visual/*.jpg` 后再生成报告 |
| 纯灰度图检测不到污渍 | `stain` 依赖饱和度通道 | 属算法特性，换彩色样本或只演示划痕/凹坑 |

## 5. 一句话速记（背诵版）

1. **是什么**：双算法工业质检平台，OpenCV 传统算子 + YOLOv8m，配置驱动、无头落盘、可 CLI 可 Web。
2. **为什么双算法**：OpenCV 漏检 60%、YOLO 漏检 13.3%，并集 90%，单算法不可接受。
3. **怎么证明**：同一张 `crazing_98`，OpenCV 判 PASS、YOLO 判 FAIL(S2)，三栏对比页一眼可见。
4. **工程化**：契约 + 配置 + 异常语义 + 251 条测试 + 版本标签。
5. **性能**：3.7 ms vs 15.0 ms，端到端 ≥ 20 FPS，可降级 YOLOv8n/s 上产线。
