# YOLOv8 三种模型对比

本文汇总本项目在 NEU-DET 数据集上实际训练过的三种 YOLOv8 变体（n / s / m），用于说明模型容量、输入分辨率与训练轮数变化对精度、速度和部署成本的影响。

三者共用同一份数据与同一套类别映射：NEU-DET 原生 6 类合并为项目契约 4 类（scratch / dent / stain / notch，见阶段 3 §4.1），训练集 1440 张、验证集 360 张（8:2 分层切分）。差异只在于骨干网络规模、输入分辨率与训练轮数。

## 1. 核心对比表

| 维度 | YOLOv8n | YOLOv8s | YOLOv8m |
| --- | --- | --- | --- |
| 参数量 | 3.2 M | 11.2 M | **25.9 M** |
| 权重体积 | 6.5 MB | 22.5 MB | 52.1 MB |
| 骨干规模（相对） | 最小 / 最快 | 中等 | 最大 / 最强 |
| 训练设备 | CPU | RTX 4060（device 0） | RTX 4060（device 0） |
| 训练轮数（epochs） | 20 | 50 | **100** |
| 输入分辨率（imgsz） | 416 | 416 | **640** |
| 批大小（batch） | 8 | 16 | 8 |
| 训练总耗时 | 0.342 h（约 20.5 min） | 0.100 h（约 6 min） | 0.989 h（约 59 min） |
| Precision | **0.7588** | 0.7825 | 0.7270 |
| Recall | 0.5955 | 0.6713 | **0.6989** |
| mAP50 | 0.7109 | 0.7579 | **0.7693** |
| mAP50-95 | 0.4003 | 0.4354 | **0.4411** |
| 30 张验证集检出率 | 86.7% | 93.3% | **100%（30/30）** |
| 单帧推理耗时 | 23.7 ms | 64.8 ms（均值）/ 48.6 ms（中位） | **15.0 ms（均值）/ 15.3 ms（中位）** |
| 推理设备（对比时） | CPU | CPU | GPU（`device: cuda`） |

> 表中加粗为该项最优值（Precision 一项 n 最高，但 n 的 Recall 明显偏低，不能单看 Precision 选型）。YOLOv8m 为 100 轮完整训练后的最终结果。

## 2. 精度维度

- **YOLOv8n → YOLOv8s**：mAP50 由 0.7109 提升到 0.7579（+0.047），Recall 由 0.5955 提升到 0.6713（+0.076），30 张样本检出率由 86.7% 提升到 93.3%。这是本项目实际收益最明显的一次升级，也是阶段 6 提交时采用的基线。
- **YOLOv8s → YOLOv8m**：mAP50 由 0.7579 提升到 0.7693（+0.011），mAP50-95 由 0.4354 提升到 0.4411（+0.006），Recall 由 0.6713 提升到 0.6989（+0.028）；30 张验证集检出率由 93.3% 提升到 **100%**（30/30）。Precision 反而由 0.7825 降到 0.7270，说明 m 更倾向于"宁可多报、不愿漏报"，这与本项目优先追求召回率的目标一致。
- **YOLOv8m 的收益来源是"容量 + 分辨率"双重加码**：参数量约为 s 的 2.3 倍，imgsz 从 416 提到 640。单看增幅（+0.011 mAP50）不如 n→s 显著，但漏检样本被彻底补齐，这是本项目最关键的指标（验证集 30 张全部至少检出一条有效缺陷）。

## 3. 速度与成本维度

- 检测阶段（是否判为缺陷）主要耗时在模型前向推理。n、s 的耗时在 `device: cpu` 下测得（23.7 ms / 48.6 ms 中位），m 改为 `device: cuda` 后测得 **15.0 ms 均值、15.3 ms 中位**——虽然 m 的参数与分辨率都最大，但在 RTX 4060 上反而比 CPU 推理的 n/s 更快，可见推理设备对耗时的影响远大于模型容量本身。
- 训练成本差异明显：n 在 CPU 上 20 轮约 20 分钟；s 在 GPU 上 50 轮约 6 分钟（416 分辨率）；m 采用 640 分辨率与 100 轮，约 **59 分钟**，是 s 的近 10 倍。
- 若产线节拍要求高（如 40+ FPS），n / s 配合 GPU 推理是更合理的落地方案；本项目作为课程项目优先追求召回率，故选 m。需要注意：m 在 GPU 上 15.0 ms/帧（约 67 FPS）本身已满足产线节拍，真正的瓶颈是显存与部署成本（52 MB 权重、约 3.3 GB 训练显存）。

## 4. YOLOv8m 最终结果与验证

- 配置：`yolov8m.pt` 预训练权重微调，`imgsz=640`，`epochs=100`，`batch=8`，`device=0`（RTX 4060 Laptop 8 GB，训练显存约 3.26 GB），训练耗时 0.989 h。
- 最终验证指标：mAP50 **0.7693**、mAP50-95 **0.4411**、Precision 0.7270、Recall 0.6989（360 张验证集）。
- 批量检出率：30 张分层抽样全部判为 FAIL（至少检出 1 条有效缺陷），检出率 **100%**；平均每帧检出 3.13 条，平均耗时 15.0 ms、中位 15.3 ms（GPU）。
- 单图验证（`test_picture/crazing_98.jpg`，置信度门槛 0.10）：检出 5 条 scratch/龟裂，置信度分别为 0.581、0.504、0.290、0.242、0.105，其中 0.581 一条被判为 **S2 重度**（`area_ratio=0.164`）。相比 YOLOv8s 时期仅检出 2 条（stain 0.486 + scratch 0.335），m 对同一张图给出了更完整的缺陷覆盖。
- 注意：0.242 与 0.105 两条低于判定层 `min_confidence=0.25`，只会出现在画框图中，不参与 PASS/FAIL 判定。

## 5. 指标口径说明

1. **mAP 指标**来自 ultralytics 训练末轮在 `datasets/neu_det/images/val`（360 张）上的验证结果，多次训练共用同一份 val 划分（`seed=42`），但 **imgsz 与 epochs 不同**（n/s 为 416，m 为 640；分别是 20 / 50 / 100 轮），因此严格意义上不是同条件对比，横向比较只反映"实际采用配置"的差异。
2. **检出率**定义为 30 张验证集样本中，经 `judge` 判定为 FAIL（至少检出 1 条有效缺陷）的比例，判定参数为 `max_count=0`、`max_area_ratio=0.01`、`min_confidence=0.25`、`min_area_px=10`，两算法共用同一套规则。
3. **单帧耗时**仅统计 `detect()` 调用，已排除模型加载与首次预热；n / s 的耗时在 `device: cpu` 下测得，m 在 `device: cuda` 下测得，**不可直接比较绝对速度**，只能说明"设备带来的差异可能大于模型容量带来的差异"。
4. 检出率为 30 张单次分层抽样结果，属方向性参考；完整汇总与逐图明细见根目录 `comparison_report.md`（本次已用 YOLOv8m 重新生成）。

## 6. 结论与选型建议

| 场景 | 推荐模型 | 理由 |
| --- | --- | --- |
| 课程项目 / 追求极致召回率 | **YOLOv8m + 640** | 30 张验证集检出率 100%，mAP50 0.7693 为三者最高，是当前项目默认配置 |
| 产线高速节拍（40+ FPS） | YOLOv8n / YOLOv8s | 参数量与显存占用小，可部署在低算力设备；牺牲部分微小缺陷召回以换取吞吐 |
| 精度与速度平衡 | YOLOv8s | 检出率 93.3%、mAP50 0.7579，相对 m 只差 6.7 个百分点召回，但模型仅为其 43% 大小 |

由于检测器参数全部由配置驱动（`model_path` / `conf_threshold` / `iou_threshold` / `device` / `imgsz` 均来自 `configs/yolo_demo.yaml`），在上述三档之间切换只需替换权重文件与配置项，无需改动任何代码——这正是"工业落地可无缝降级"的实现基础。
