# 彩色域外评估：FabricDefect（2026-10-27）

> 一句话结论：**链路能跑彩色图，但两个算法在这批彩色织物上都不能可靠检出缺陷**。OpenCV 几乎不触发 `stain` 分支，YOLO 属域外输入；结果是“可跑通、不可用”，因此不把彩色检测写进能力声明，主 demo 仍以灰度 NEU-DET 为准。

本文与 `OpenCV_vs_YOLO_对比分析.md` 互补：那份文档回答“NEU-DET 域内谁更强”，本文回答“换一个彩色域会怎样”。两批数据不同域，指标不可横向相加。

---

## 1. 结论摘要

| 维度 | 实测结论 |
| --- | --- |
| 彩色输入可跑通 | 是。`inputs/image_source.py` 用 `cv2.IMREAD_COLOR` 读图，彩色图保持三通道，Pipeline / 判定 / 可视化 / 报告全程无异常 |
| OpenCV 能否找到缺陷 | **基本不能**。143 个框里 `dent=124 / scratch=19 / stain=0`；119/143 框中心落在 GT 外；GT 像素覆盖最高仅 2.4%；0/24 图覆盖 ≥5% |
| YOLO 能否找到缺陷 | **部分能、但不可信**。29 个框（`conf≥0.10`），20/29 框中心在 GT 外，9/24 图零检出；14/24 图覆盖 ≥10%，但其中多例靠“大框罩住整块区域”虚高，6/24 图与 GT 的 best IoU ≥0.3 |
| 结论定性 | 彩色织物对 `best.pt` 是**域外输入**；对 OpenCV 是**纹理场景不匹配**。两者都不是“再调个阈值就能解决”的问题 |
| 决策 | 不把彩色检测作为当前版本能力；不做 NEU-DET + FabricDefect 直接混训（见 §7） |

## 3. 实验设置

| 项 | 设置 |
| --- | --- |
| OpenCV | `configs/demo.yaml`；`min_confidence=0.45`、`stain_sat_min=60`、`stain_color_dist_min=30.0`；**未调参** |
| YOLO | `configs/yolo_demo.yaml`；`best.pt`（YOLOv8m，NEU-DET 权重）、`conf_threshold=0.10`、`iou_threshold=0.45`、`imgsz=640`、`device=cuda`；**未调参** |
| GT 口径 | 掩码外接矩形（因是弱标注，GT 面积天然偏大） |
| 阈值敏感性 | YOLO 额外按 `cut=0.25 / 0.45` 重聚合，观察置信度变化趋势；OpenCV 内部已按 0.45 过滤，故三档结果一致 |

**指标定义**（仅内部对比，不等同官方 mAP）：

- `hits_center`：检测框中心落在 GT 矩形内 → 记为命中；
- `fp_center`：检测框中心落在 GT 矩形外 → 记为误检；
- `coverage`：所有检测框并集覆盖 GT 像素的比例（**会被超大框虚高**）；
- `best_iou`：与 GT 外接矩形的最大 IoU（弱 GT 下偏宽松）。

## 6. 原因分析

### 6.1 “能跑彩色” ≠ “能懂彩色”

输入层 `inputs/image_source.py:57,100` 用 `cv2.IMREAD_COLOR` 统一读成三通道，所以彩色图能进 Pipeline、能出标注图和报告。但**算法层是否利用了颜色**是另一回事：

- 结构类缺陷（`scratch` / `dent` / `notch`）走灰度：`detectors/opencv_detector.py:264` 的 `_preprocess` 先 `cv2.cvtColor(BGR2GRAY)`，颜色信息在这一步就丢了；
- 只有 `stain` 分支真正用颜色：`opencv_detector.py:352-378`，HSV 饱和度阈值 + Lab 色距。

### 6.2 为什么 OpenCV 的 `stain` 一个都没触发

`_detect_stain` 先算全图 Lab 中位数当背景，再要求 `色距 ≥ 30` **且** `HSV 饱和度 ≥ 60`。织物缺陷绝大多数是**亮度/纹理/结构**变化（断经、划痕、破洞），不是“颜色偏离背景”。这批图背景本身是有纹理的彩色布面，中位数背景模型不稳定：

- 纹理边缘被当成“色差”，于是 `dent` 误检爆炸（124 框）；
- 真正的缺陷区域色距不足 30，`stain` 恒为 0。

即 `stain` 分支设计目标是“异物/油污落在单色背景上”，与织物域不匹配。

### 6.3 为什么 YOLO 会差

`best.pt` 在 NEU-DET（灰度热轧钢表面）上训练，学到的特征分布是“灰度、金属、有明确对比度的条状/点状缺陷”。彩色织物属于典型域外：

- 颜色分布、纹理频谱、缺陷形态三项都不同；
- 模型仍会强行输出 NEU-DET 四类之一，表现为**类别错配**（织物污渍被判成 dent，破洞被判成 stain）；
- 域外推理没有“未知类”出口，置信度也不代表可靠性。

所以“YOLO 没在这个测试集上训练”是部分原因，但**根本原因是域差**；把 FabricDefect 加进训练集（且不改标签协议）还会引入新问题（见 §7）。

### 6.4 指标本身要打折看

- `coverage` 会被“一个框罩住整张图”刷到 100%；
- `best_iou` 对矩形弱 GT 偏宽松；
- `hits_center` 对细小缺陷偏严格。

三个指标必须一起看：`Fabric19` 就是 coverage 100% + IoU 0.75 但中心命中 0 的典型“指标好看、实际没用”。

## 7. 决策与后续

### 7.1 已定决策

1. **不把“支持彩色缺陷检测”写进 README / 答辩口径**。准确表述是：“平台可接受彩色输入并完整落盘，但检测能力只对 NEU-DET 灰度金属域有效。”
2. **主 demo 继续用灰度 NEU-DET**（`configs/demo.yaml` / `yolo_demo.yaml` / HTML 两份）。
3. **不做 NEU-DET + FabricDefect 直接混训**。原因：
   - 分布冲突：灰度金属 vs 彩色织物，backbone 特征要同时拟合两种完全不同的底层分布；
   - 标签语义冲突：NEU-DET 六类合并成 4 类，FabricDefect 的“破洞/断经/污渍”与 `dent/stain` 语义并不等价，硬凑会造成类别漂移；
   - 灾难性遗忘：小数据（24 张）混入大数据的常见结果是原域指标下降、新域也学不好，即“两边都不准”。
4. **彩色样本目录不入库**（`.gitignore:49`），只作本地已知限制验证。

### 7.2 如确实要做彩色能力，两条路线（成本差异大）

| 路线 | 做法 | 成本 | 预期 |
| --- | --- | --- | --- |
| A. 仅演示 | 新增 `configs/color_demo.yaml`，放宽 `min_confidence` / `stain_color_dist_min`，只做“链路能出框”的演示 | 小（半天） | 能出图，但必须如实标注“高误检、不可用于判定” |
| B. 真做检测 | 准备彩色域**强标注**（多边形/框级精标），单独训练一个彩色权重或多域联合训练（冻结部分 backbone、领域随机化、各域独立测试集） | 大（数天～数周） | 才谈得上“支持彩色”，且必须保留独立测试集评估 |

当前没有彩色强标注数据，B 路线不启动。
